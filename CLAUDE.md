# Dao to HSK — Motion

Анимационные ролики для курса китайского языка Dao to HSK: интро к урокам,
позже промо. Героиня — стилизованный образ Риты (преподаватель курса, жена
владельца). Сайт курса — отдельный репозиторий `dao-to-hsk`.

## Как работать с владельцем проекта

- Владелец (Даниил) учится разработке. Общение и объяснения на **русском**.
- Идём маленькими шагами. Перед каждым шагом коротко: что делаем и зачем.
  После шага: что получилось и как это проверить (кадр, превью, MP4).
- Новые понятия (таймлайн, параллакс, кодек, alpha-канал и т. п.) объясняй
  простыми словами на примере этого проекта.
- Крупные задачи сначала планируй и согласуй, потом пиши код.
- Спрашивай перед необратимым: push, merge, удаление файлов, установка
  программ и зависимостей, загрузка чего-либо во внешние сервисы.
- Если что-то не получилось, честно скажи об этом и покажи вывод ошибки.

## Личные данные

- Фото Риты — личные данные. Не загружать во внешние сервисы (генераторы
  картинок, хостинги) без её явного согласия на конкретный сервис.
- Фото не коммитим: они лежат только локально в `refs/private/` (в `.gitignore`).
  В репозитории — только словесное описание: `docs/character-rita.md`.
- Татуировки персонажу не рисуем.

## Как делаем ролики

Основа — скилл `vizavi-motion` (`.claude/skills/vizavi-motion/`). Его три правила
обязательны:

1. **Качество:** камера живая, с параллаксом планов; текст участвует в действии;
   музыка и звук синхронны событиям.
2. **Сначала раскадровка:** на каждую сцену 3–5 вариантов, выбор лучшего,
   короткая проба главного риска до полной сборки.
3. **Первая сборка — черновик:** просмотреть, исправить, проверить готовый MP4.
   Честные статусы: «реализовано», «проверено запуском», «видно в кадрах»,
   «проверено в движении», «прослушано».

Техника:

- Ролик — HTML + SVG/Canvas без сборщика и без Node.js. Вся анимация — функция
  `renderAt(t)` от времени, без `requestAnimationFrame`-накоплений и
  `Math.random()` без seed: кадр должен получаться одинаковым при любом порядке.
- Рендер: Python + Playwright снимает кадры по времени `i / fps`, FFmpeg
  собирает MP4. Зависимости Python — через `uv`, pip напрямую не используем.
- Выход по умолчанию: MP4 1920×1080, 60 fps, H.264, yuv420p, AAC.
- Проверка результата: `ffprobe` готового файла + просмотр кадров на границах сцен.

## Стиль и бренд

- Тушь + акварель, приглушённые цвета, бумажная фактура. Референс стиля —
  у владельца (акварельный портрет в конической шляпе), в репозиторий не кладём.
- Палитра и шрифты бренда «Тушь» — `docs/brand.md`. Не выдумывай новые
  фирменные цвета; акварельные оттенки — приглушённые, рядом с палитрой.
- Любой иероглиф в кадре показываем с пиньинем (правило бренда).
- Китайский текст (иероглифы, пиньинь с тонами) должен быть точным. После
  изменения — проверка агентом `chinese-checker`.
- Достопримечательности рисуем узнаваемыми по силуэту; при сомнении в
  деталях (число ярусов пагоды и т. п.) отметь это и попроси проверку.

## Музыка и чужие материалы

- Только бесплатные материалы с понятной лицензией, разрешающей YouTube и
  коммерческое использование. Для каждого файла в `music/` — запись в
  `music/CREDITS.md`: название, автор, ссылка, лицензия, дата.
- Чужие видео, модели и шрифты из референсов в ролик не вставляем.

## Структура

```
docs/HISTORY.md          журнал проекта: решения, проблемы, уроки
docs/brand.md            палитра и шрифты бренда для роликов
docs/character-rita.md   описание персонажа (вместо фото)
docs/intro-01-plan.md    план первого ролика
characters/rita/         SVG персонажа по слоям
videos/<ролик>/          сцены и таймлайн ролика
shared/                  общий код: таймлайн, фильтры туши и акварели
render/                  рендер кадров и сборка MP4
music/                   музыка и звуки + CREDITS.md
out/                     кадры и MP4 (не в git)
```

## Git

- `main` — всегда рабочая версия. Задачи — в ветках `feature/...`, `fix/...`,
  `docs/...`, в `main` через Pull Request после проверки владельцем.
- Коммиты небольшие, сообщение на английском в повелительном наклонении.
- Код и комментарии в коде — на английском; документация — на русском.
- Большие бинарные файлы (кадры, MP4) не коммитим. Музыку — можно, если
  лицензия разрешает распространение; иначе только ссылка в `CREDITS.md`.

## Готово, когда

1. Ролик собран в MP4 и `ffprobe` подтверждает формат, длительность и звук
2. Ролик просмотрен: начало, конец, стыки сцен; найденные дефекты исправлены
3. Китайский текст проверен `chinese-checker`
4. Владелец посмотрел и одобрил
5. Решения и проблемы записаны в `docs/HISTORY.md`
